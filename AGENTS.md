# AGENTS.md

## Project

This is the personal website of Prateek Pal, "The Long Way Home".

The website is a Next.js application using:
- Next.js App Router
- React
- TypeScript
- Tailwind CSS
- OpenNext for Cloudflare Workers

The website contains:
- Homepage
- Journal
- Projects
- About

## Architecture

The website has two content sources:

1. Hand-authored content in `content/journal/`
2. Published content generated by the separate Studio publishing backend

Published content lives in:

`content/published/`

The publishing pipeline is:

Studio → GitHub publication → `content/published/` → build-time generation → loaders/adapters → website pages

There are no runtime CMS requests for published content.

## Studio

Studio is a separate sibling application and acts as the publishing backend.

Do not assume Studio behavior. Inspect the Studio repository when a task depends on it.

The relationship between Studio and Website is important and should be preserved.

## Publishing Contract

Published documents follow Publishing Contract v0.1.

Important concepts include:
- `contractVersion`
- `id`
- `contentType`
- `slug`
- `publishedAt`
- `metadata`
- `blocks`

Do not change the publishing contract or publishing pipeline without explicitly discussing the consequences first.

## Images

Published images are stored in Cloudflare R2.

Published documents contain absolute R2 URLs.

Do not replace or rewrite image URLs without understanding the existing image pipeline.

## Development Rules

Before modifying code:

1. Inspect the relevant files.
2. Understand the existing implementation.
3. Explain the intended change.
4. Keep the change narrowly scoped.
5. Do not refactor unrelated code.

When possible, verify changes with the appropriate build, type-check, lint, or test command.

## Git Safety

Do not commit changes unless explicitly asked.

Do not reset, delete, or overwrite user work.

Before making significant changes, inspect the Git working tree.

Always keep unrelated changes untouched.

## Design Philosophy

The website should remain:
- minimal
- calm
- content-focused
- personal
- readable
- spacious
- intentional

Avoid unnecessary UI complexity, animations, abstractions, or dependencies.

Prefer simple solutions that fit the existing architecture.

## Important Principle

When uncertain, inspect the code and existing documentation rather than guessing.

Clearly distinguish between:
- verified facts
- reasonable inference
- unknown behavior

Never present an inference as a verified fact.
